## Update

Activity reads no longer return the audit-only `ip_address` and `user_agent`
columns. Every board viewer could read the IP address and browser string of
other users, and anonymous visitors could on PUBLIC boards. The four
client-facing reads now select explicit columns, as
`GET /api/v1/boards/:id/activities` already did:

- `GET /api/v1/boards/:id/activity`
- `GET /api/v1/boards/:id?include=activities`
- `GET /api/v1/cards/:id/activity`
- `GET /api/v1/cards/:id?include=activities`

Response shapes are otherwise unchanged (`id`, `entity_type`, `entity_id`,
`board_id`, `action`, `actor_id`, `payload`, `created_at`, plus the existing
actor fields). Writers still store both columns for audit.

## New

- `tests/db/activityReadPrivacy.ts` runs the four real handlers against a
  disposable PostgreSQL database with an activity row carrying an IP and user
  agent, and asserts each returns the row without either column. The two board
  feeds are requested anonymously on a PUBLIC board. Run with
  `CHIMEDECK_TEST_SANDBOX=1 DATABASE_URL=postgres://.../chimedeck_test bun run tests/db/activityReadPrivacy.ts`.
  The `board-members` CI job lints and runs it.

## Technical Debt

Other readers of `activities` were checked and do not reach a response body
with these columns: the Trello-compatible actions and card actions build
explicit objects, notifications select only `payload`, the realtime
`card_activity_created` event picks fields, and historical import only uses
the row for existence checks and fingerprints. `writeActivity` still returns
the full row (`returning *`); no caller sends it to a client today.

## What Should Be Done Next

Review and deploy through the normal release process. Any new activity read
should select explicit columns rather than `activities.*`.
