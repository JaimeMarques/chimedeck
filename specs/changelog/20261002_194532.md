## Update

Cards now record who created them. Every card insert with an acting user
stores that user in `cards.created_by`: create, copy, duplicate, checklist item
conversion, board duplicate, the `card.copy_to_board` automation action, the
Trello-compatible `POST /cards`, and historical import card creates (the
resolved `historical_author`). `get_card` returns the column with the row, and
the list-cards endpoint now selects `c.created_by`. A request without a user
stores `NULL`, never `'system'`. The Trello seed import has no actor and
leaves it `NULL`.

## New

- Migration `0125_card_created_by` adds nullable `cards.created_by`
  referencing `users.id` with `ON DELETE SET NULL`, and backfills existing
  cards from their `card_created` activity. With several rows, one whose
  payload has `trello_action_id` wins, then the earliest `created_at`
  (`DISTINCT ON`). The winner is kept only when it is a real user, so
  `'system'` and unmapped actors stay `NULL` rather than falling back to a
  weaker row. `down()` drops the column.
- `server/extensions/card/api/create.test.ts` checks that create stores the
  user and `NULL` without one. Run
  `bun test server/extensions/card/api/create.test.ts`.
- `tests/db/cardCreatedByBackfill.ts` checks the backfill on a disposable,
  fully migrated PostgreSQL: it rolls back only 0125, seeds single-user,
  Trello-plus-native, earliest-native, `'system'`, unknown-actor,
  unmapped-Trello-plus-native-user and no-activity cards, runs it up, repeats
  down/up, and checks the `SET NULL` foreign key. It needs
  `CHIMEDECK_TEST_SANDBOX=1` and a local `DATABASE_URL` with a test name.

## Technical Debt

No code in this repository writes `trello_action_id` into activity payloads;
the backfill preference serves rows written by earlier imports. Cards with no
`card_created` activity, or whose winning actor is not a user, stay `NULL`.
The card unit tests share Bun module mocks, so `bun test server/extensions/card`
as one run already fails `move.test.ts` on `main`; CI runs these files one by
one. The backfill is one `UPDATE` inside the migration transaction
(`lock_timeout` 5s).
