## Update

`POST /api/v1/boards/:boardId/members` no longer rewrites an existing member's
role, and no longer accepts a role it cannot store.

The handler treated a duplicate add as an idempotent role update, with `role`
defaulting to `MEMBER` whenever the body's role was absent or not in
`VALID_ROLES`:

```ts
if (existing) {
  await db('board_members').where(...).update({ role, ... });
}
```

Two consequences. A board ADMIN could be silently demoted: `POST {userId}` with
no role on an existing admin rewrote their role to `MEMBER`, bypassing the
last-board-admin guard in `members/update.ts` and leaving a board with no admin
at all — the exact state that route refuses to create. And `observer` was
swallowed: `VALID_ROLES` holds uppercase `ADMIN`/`MEMBER` while the MCP
`invite_to_board` tool offers lowercase `member`/`observer`, so both fell
through to the `MEMBER` default and a caller asking for `observer` got a full
member with no error.

Changes in `server/extensions/board/api/members/create.ts`:

- A duplicate membership returns `409 board-member-exists` and performs no
  write, pointing the caller at `PATCH /api/v1/boards/:boardId/members/:userId`
  — the route that enforces the last-ADMIN invariant. The insert itself is the
  authority rather than a preceding read: `board_members` carries
  `UNIQUE (board_id, user_id)` (migration 0040), so a read-then-insert would let
  two concurrent adds both pass the check and surface PostgreSQL `23505` as a 500. `onConflict(...).ignore()` makes the losing writer return zero rows,
  which is reported as the documented 409.
- `normalizeBoardMemberRole()`: an omitted POST role still defaults to
  `MEMBER`; supplied strings are trimmed and upper-cased, while `null`,
  non-strings, and anything outside `ADMIN`/`MEMBER` are rejected with
  `400 invalid-role`. PATCH uses the same normalization without the default.
- The success status is now always `201`; the `200` branch existed only for the
  removed update path.

POST, PATCH, and DELETE now share one management policy: workspace `ADMIN+` or
an exact explicit board `ADMIN`. A workspace `GUEST` cannot inherit that power
from a stale `board_members` row, and schema-invalid legacy role strings are not
treated as privileged. All workspace-membership and board-member writes now
acquire a workspace advisory lock before any per-board lock. That order keeps
authorization current, prevents add/join/board-creation races from resurrecting
orphan board rows, and avoids promotion/removal deadlocks. Eligible-admin counts
exclude GUEST and orphaned memberships, but those stale rows remain removable.
Native and Trello-compatible workspace removal share the same cleanup and
last-active-board-admin guard.

PUBLIC boards remain anonymously readable, but mutating requests now run the
normal authentication and workspace-membership middleware before dispatch. The
member-added event keeps the persisted/realtime `board_member_added` name for
compatibility, while dispatch normalizes it to `board.member_added` plus
`memberId` for automation. Webhook delivery for this event is restricted to a
webhook owned by the newly added member, as its event contract requires.

Compatibility: `src/extensions/Board/components/BoardMembersPanel` filters
existing board members out of its add candidates, now exposes only the two
roles the database can store, and always sends an explicit uppercase role.
Callers that used POST to change a role must switch to PATCH. POST accepts either
`userId` or the email shape used by the first-party CLI/MCP clients. The MCP
tool now advertises only the persisted `member` and `admin` roles.

## New

- `server/extensions/board/api/members/__tests__/addBoardMember.test.ts` and
  `__tests__/fixtures/addBoardMember.ts` — regression coverage run in a
  subprocess with a faked db chain. Written RED first against the old handler:
  the duplicate, invalid-role and case-insensitivity cases all failed before the
  fix and pass after it. Covers insert-as-member, duplicate conflict, invalid
  role, `admin` accepted in any case, and the unchanged workspace-membership
  gate.
- `tests/db/concurrentBoardMemberAdd.ts` — a PostgreSQL-backed regression for
  the race the fake-DB tests cannot express. A SHARE table lock allows reads
  while blocking inserts; the test observes both waiting inserts in `pg_locks`
  before releasing the barrier. Both old absence checks must therefore finish
  before either write. Requires one `201`, one `409`, and one membership row;
  the same test fails with `23505` against the read-then-insert revision. It
  also races self-join requests, requires `200`/`201` with one row, verifies the
  backward-compatible realtime event plus automation `memberId` payload, and
  proves queued POST/self-join requests cannot outlive workspace removal.
- `tests/db/concurrentBoardMemberRoleMutation.ts` — a PostgreSQL-backed
  regression for the last-ADMIN invariant. It deterministically races two
  demotions and then two removals; each pair must produce one `200`, one `409`,
  and leave one ADMIN. The PATCH and DELETE handlers now share a transaction-
  scoped locks, so their count-and-mutate decisions serialize. The test fails against the unlocked
  handlers with two `200` responses and zero remaining administrators. It also
  covers stale-row cleanup, cached and queued authorization revocation,
  concurrent Trello-compatible role writers, Trello stale-GUEST authorization,
  and Trello workspace-member removal.
- `server/mods/events/__tests__/policy.test.ts` covers the pure event policy;
  `dispatch.test.ts` exercises the real dispatcher integration and proves both
  automation normalization and fail-closed webhook recipient filtering.
- `tests/e2e/board-members.spec.ts` uses the mounted `/auth/token` route and
  `data.accessToken`, provisions real users and workspace memberships, and
  reads roles back after duplicate POST and PATCH. It tests a workspace MEMBER
  who is first denied as board MEMBER, then permitted as board ADMIN. Against
  the revision without the PATCH fallback, the latter assertion receives 403.
  It also covers authenticated writes to PUBLIC boards, lowercase PATCH role
  normalization, board-admin DELETE, and a remove/reinvite-as-GUEST sequence
  that cleans the board row and must not reactivate board-admin privileges. A
  workspace removal case also proves that the only active board ADMIN cannot be
  removed. The last-admin cases now use the user's id, not their token.
- `test:db:board-members` and `test:e2e:board-members` run in a dedicated CI
  job with a fresh PostgreSQL service, migrations, temporary JWT keys, and the
  real server. Focused ESLint and `tests/tsconfig.json` TypeScript gates cover
  the regression sources. The Playwright cases exercise HTTP; no browser binary
  is needed.

## Technical Debt

The HTTP suite creates disposable accounts and workspaces; run it only against
an isolated test instance, as CI does. It does not prove browser UI behavior.
