## Update

The shared MCP registration now exposes 60 tools in both stdio and HTTP
sessions: the 20 existing tools, unchanged, plus 40 board coverage tools ported
from the local Python `chimedeck-mcp` server with identical tool and camelCase
argument names, so agents switch servers without changes. The MCP README,
in-product Developer Docs and MCP scenario index document every new tool.

## New

- Lookups (`readOnlyHint`): `get_me`, `list_workspaces`,
  `list_workspace_boards`, `list_workspace_members`, `get_board`,
  `list_lists`, `list_labels`, `list_board_members`, `list_cards`,
  `list_archived_cards`, `get_comments`, `get_attachments`,
  `download_attachment`.
- Card writes: `update_card`, `set_card_due`, `archive_card`, `delete_card`,
  `copy_card`. PATCH bodies use the server's snake_case `due_date` /
  `due_complete`.
- Comments and attachments: `edit_comment`, `delete_comment`,
  `add_url_attachment`, `delete_attachment`. `download_attachment` streams
  `GET /attachments/:id/view` with the caller's token and returns an image
  block or a base64 embedded resource, capped at 10 MB; nothing is written to
  the server's disk.
- Labels and members: `add_card_label`, `remove_card_label`, `create_label`,
  `delete_label`, `add_card_member`, `remove_card_member`,
  `add_board_member`, `set_board_member_role` (`admin` / `member`).
- Checklists, lists and boards: `create_checklist`, `add_checklist_item`,
  `set_checklist_item`, `rename_checklist`, `delete_checklist`,
  `delete_checklist_item`, `rename_list`, `archive_list`, `delete_list`,
  `update_board`.
- Every write returns the object read back after the change; deletes verify
  the object is gone and return a small confirmation (`delete_comment`
  returns the server's soft-delete placeholder). A disagreeing read-back
  is an error (`readback-failed`, `delete-failed`); null, HTML-200 and
  wrong-shaped responses are `invalid-response`. Every requested field is
  compared on the read-back (text trimmed and sanitized as the server's
  handler stores it). A DELETE succeeds only with its route's real answer
  (`204`, or `200` naming the row for attachments and comments). Tokens never
  appear in output.
- Tools taking a parent ID next to a child ID (`delete_checklist`,
  `delete_checklist_item`, `delete_attachment`, `delete_label`,
  `delete_list`, `rename_list`, `archive_list`, `edit_comment`,
  `delete_comment`) read the parent first and fail with `not-in-card` /
  `not-in-board` before any write when the child is elsewhere.
- `archive_card` and `archive_list` resolve the UUID (short IDs included) and
  current state first because the server archive routes toggle; repeated
  calls keep the requested state, and any other post-state is
  `archive-state-conflict`.
- Shared helpers (`tools/toolSupport.ts`) and an isolated-subprocess MCP/HTTP
  fixture (`tools/toolSupport.fixture.ts`); a registration test asserts 60
  unique tool names. `specs/tests/mcp/mcp-11-board-coverage.md` records manual
  acceptance. The MCP CI job now runs all of `server/extensions/mcp` and lints
  every new MCP file.

## Technical Debt

- `delete_list` sends no `confirm`, matching Python, so the server refuses any
  list that still has cards (`delete-requires-confirmation`).
- `add_url_attachment` keeps Python's optional `name` and sends the URL as the
  name when it is omitted, because the server requires one.
- `edit_comment` / `delete_comment` read a reply back from its parent's
  replies. `delete_comment` returns the server's soft-delete placeholder for a
  top-level comment rather than proving absence.
- `update_card` / `set_card_due` send `dueDate` as a UTC instant, so a bare
  date means UTC midnight rather than the database session's timezone.
- A concurrent archive/restore by another client between the archive tools'
  state read and their PATCH can still flip the object, because the routes
  toggle; the tools then report `archive-state-conflict` rather than fix it.
- Attachment and comment rows expose no short ID, so their scoped tools need
  the UUID (a short ID fails closed with `not-in-card`).
- Python's `observer` board role is not offered: the server accepts only
  `ADMIN` and `MEMBER`.
- Full `bun run typecheck` still reports the baseline errors outside the MCP
  files; no new diagnostics were added.

## What Should Be Done Next

Review and deploy through the normal release process, then reconnect MCP
sessions so they discover the new tools. Decide whether `delete_list` should
take a `confirm` argument; it would diverge from the Python server.
For the server maintainer, as information: an explicit `archived: boolean`
body on `PATCH /cards/:id/archive` and `PATCH /lists/:id/archive` (set rather
than toggle) would make archiving atomic and idempotent, closing the
concurrent-toggle window the MCP side can only detect.
