## Update

`get_card` previously always returned `includes.activities = []`, because the
REST card endpoint loads activities only on `?include=activities`. The tool now
URL-encodes `cardId`, so a crafted ID cannot add query parameters or path
segments to the REST request. Calls without the new flag hit the same path as
before. The MCP README, in-product Developer Docs and both `get_card` test
scenarios document the parameter.

## New

- `get_card` accepts an optional boolean `include_activities` (default false).
  When true it requests `GET /api/v1/cards/:cardId?include=activities` and the
  response carries the card's activity feed in `includes.activities`, oldest
  first; when present, the `card_created` row's `actor_id` is the card's creator (some cards have none).
- `getCard.test.ts` covers the default path, flag true and false, and an
  injected card ID. Run `bun test server/extensions/mcp/tools/getCard.test.ts`.

## Technical Debt

The activity feed is not paginated by the REST endpoint; a long-lived card
returns every visible row. No pagination is added here.
