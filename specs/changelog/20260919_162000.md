## Update

After PR #7 landed email input, MCP role corrections, and stronger membership locking, PR #9 is reduced to the remaining email-lookup safeguards. Its branch merges current `main` without rewriting published history.

- Resolve email only among non-GUEST members of the board's workspace, using `LOWER(u.email)` and distinct user IDs. Lowercasing only the input misses mixed-case stored addresses.
- Reject multiple eligible normalized matches with `409 ambiguous-email`, directing callers to `userId` rather than granting privileges to an arbitrary account. Fetch at most two distinct IDs, sufficient to detect ambiguity.
- Return identical `422 user-not-workspace-member` status and body for unknown, outside-workspace, and GUEST addresses. A global lookup followed by differing 404/422 responses reveals account existence.
- Resolve the email after workspace/board locks and fresh manager authorization, so eligibility changes while queued cannot leave a cached recipient ID. Preserve the existing lock order, duplicate rejection, events, and target membership recheck.
- Keep `userId` precedence. The UI sends `userId`; MCP sends email and already surfaces structured errors. No MCP schema or documentation rollback is needed.
