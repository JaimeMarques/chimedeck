## Update

The shared MCP registration now exposes discussion reads in both stdio and
HTTP sessions. Existing tool names, schemas and response shapes are unchanged.
The MCP README and in-product Developer Docs include parameters, examples,
ordering, completeness semantics and session/allowlist refresh instructions.

## New

- `get_card_discussion(cardId)` reads top-level comments and their non-deleted
  direct replies through existing authenticated REST GET routes. It preserves
  comment fields and parent relationships, grouping oldest-first replies after
  oldest-first parents without reordering timestamp ties.
- `get_comment_replies(commentId)` reads a single parent UUID, including
  uppercase UUID input. Both readers advertise `readOnlyHint` and return
  `{data, complete, issues}`. Per-thread failures, inconsistent reply counts,
  malformed reply records and unexpected response metadata are explicit;
  successful threads are retained. Failed initial/direct reads are MCP errors.
- Twenty-six isolated protocol/HTTP tests cover fresh tool discovery,
  GET-only calls, caller-token forwarding, unthreaded/threaded reads, ordering,
  validation, redaction, failures and unknown pagination metadata. Run
  `bun test server/extensions/mcp/tools/readDiscussion.test.ts`.
- `specs/tests/mcp/mcp-10-discussion.md` records manual read-only acceptance.
- A focused MCP discussion CI job runs the protocol cases, server/test lint
  and client build on main pull requests without credentials or services.

## Technical Debt

Reads across endpoints are not an atomic snapshot. The existing API supports
one reply level and no pagination, and excludes deleted reply bodies. No
pagination protocol is invented and no comment write behavior is changed.

Validation on Bun 1.3.14 with frozen dependencies: 26 focused tests and server/
test-file ESLint pass; `bun run build:client` passes. Fresh stdio MCP retrieved
an existing live reply with the correct body, author and parent, without writes.
The actual Developer Docs component was rendered locally in Chromium at desktop
and mobile sizes; both navigation anchors and completeness guidance passed.

Full `bun run typecheck` remains blocked by 172 identical baseline errors on
`3de62f085af4d868c57c3e0ce7156cf264e5dc3a` and this branch (normalized checkout
paths). The docs page retains its four baseline ESLint errors: an existing
void-expression callback and three references to an unconfigured React lint
rule. No new errors were introduced; these are not green full-project gates.
