## Update

Comment-editor image uploads are scoped to comments, excluded from card
attachment lists/counts and attachment-added activity, and associated atomically
with their author and card on create/edit. Create, list, edit and reply responses
carry image metadata. Ordinary attachments retain their existing behavior.

New image markdown uses stable attachment IDs so duplicate filenames resolve
correctly; existing filename references remain readable without backfilling.
Confirmed upload responses now provide the same proxy URLs as attachment lists.
CommentItem keeps canonical proxy sources separately while revoking blobs, avoids
displaying pending-scan JSON as an image, and retries actual pending responses
while mounted with a delay capped at ten seconds and a processing placeholder.

## New

Migration 0124 adds upload context, nullable comment ownership, confirmation
time and an explicit abandonment timestamp. Confirmed drafts survive long
editing sessions and offline replay for thirty days after confirmation.
Never-posted confirmed images expire after that fallback TTL. Removed/deleted-comment images expire one
hour after abandonment; unfinished uploads retain their one-hour creation TTL.
Claimed images are protected by a transaction lock. Existing attachment rows
stay card attachments; migration does not remove legacy duplicate entries.
Comment image boundary, duplicate filename
and DOM lifecycle regressions accompany a local acceptance scenario.

## Technical Debt

The full app/database/LocalStack flow and migration have not been exercised in
this environment. Browser proof covers the real CommentItem in an isolated
fixture, including rerender and fetch failure. Full typecheck has inherited
diagnostics; focused checks do not make that full gate green.

Legacy duplicate filename references remain inherently ambiguous. No destructive
backfill is attempted.

## What Should Be Done Next

Review and deploy the migration with the application, then run the documented
local acceptance scenarios with scanning and LocalStack enabled.
